# Stack research

What the code can't show about magrippis.com's stack: why it is set up as it is, what was ruled out, and what breaks. Each entry holds at the versions it names. Everything runs on the latest release of each tool, except where Constraints says otherwise. pnpm installs no release younger than a day, its `minimumReleaseAge` default, so the latest release is the newest one at least a day old. https://pnpm.io/settings/dependency-resolution

## Decisions

- Playwright starts `vp run preview`, which is `wrangler dev` serving `build/` with `apps/web/wrangler.jsonc`, so the specs see the site as Cloudflare serves it. `vp preview` applies neither `_headers` nor `_redirects`, and answers a wrong address from Kit's server rather than with `404.html`. Playwright never reuses a server already on port 4173, which is also Vite's default for `vp preview`, so it can't test the wrong server or one still serving an old build: it stops with "http://localhost:4173 is already used, make sure that nothing is running on the port/url or set reuseExistingServer:true in config.webServer." https://developers.cloudflare.com/workers/static-assets/headers/
- The `playwright` task is never cached. Against a deployment, a run's result depends on that site rather than any local file, so a cache hit would replay a stale result. https://viteplus.dev/config/run
- Trispace's latin subset is preloaded, through the `preload` option of the `handle` hook, and the other subsets are not: no page's text needs them. Chromium holds first paint for a font preloaded in the head until it loads, for at most 100 ms after the last stylesheet and 1.5 s after navigation, so text paints in Trispace from the start. https://chromium.googlesource.com/chromium/src/+/refs/heads/main/third_party/blink/renderer/core/loader/render_blocking_resource_manager.cc
- When the font misses that window, fontaine's fallback face stands in, built from monospace system fonts such as Courier New. Trispace's glyphs come in three widths, 0.5, 0.65 and 0.85 em, which a monospace face scaled to their average matches line by line. With the font held back 2.5 s, the swap shifts the home page by 0.0009, against 0.111 for Arial and 0.173 with no fallback face. https://github.com/unjs/fontaine
- Stock Android has none of fontaine's monospace faces, so Cutive Mono joins them. Chrome on Android matches `local()` against every font in `/system/fonts` by full and PostScript name, and AOSP's `fonts.xml` ships two monospace families: Droid Sans Mono, which capsize has no metrics for, so fontaine can't size a face from it, and Cutive Mono, which it has. https://chromium.googlesource.com/chromium/src/+/refs/heads/main/content/browser/font_unique_name_lookup/font_unique_name_lookup_android.cc https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/data/fonts/fonts.xml
- A post's Markdown becomes HTML in Kit's server code as the post page and the feed prerender, not in content-collections' transform, which runs outside Vite and so can't import an image through enhanced-img. `import.meta.glob` sends the JPEGs and PNGs next to a post through enhanced-img and imports its WebPs as they are. The feed renders the same Markdown with `SITE_URL` before every image URL, since a reader resolves no relative one. The images sit next to their post, so its Markdown previews on GitHub and in editors.
- A post's still gets widths from 540 pixels up, with `sizes` set to the post column. Given neither `w` nor `sizes`, enhanced-img takes a source to be twice the size it shows at: it writes a half-width and a full-width file with `1x` and `2x` descriptors, so a 1x screen showing a 1560-pixel screenshot in the 998-pixel column would get 780 pixels. https://svelte.dev/docs/kit/images
- A post's animations are WebP, converted once from the GIF with sharp at quality 80 and committed: 37% of the bytes Giphy served for the same 21 animations at the same size. The build stops on a WebP with one frame, which belongs in JPEG or PNG so enhanced-img serves it in AVIF.
- A post's animation stops within 5 seconds, W3C technique G152 for WCAG 2.2.2, through a WebP loop count of as many whole passes as fit. Chromium 159, Firefox 159 and WebKit 27.2 play a WebP exactly its loop count of times, without GIF's extra pass: a 3.57 s animation stopped after 3.5 to 3.6 s at a count of 1 and 7.1 s at 2. They show a WebP frame for its own duration, 0 ms included: ten frames of 0 ms played out within 0.1 s. The build stops on an animation that would play longer. https://www.w3.org/WAI/WCAG22/Techniques/general/G152 Giphy's best original is `source.gif`, the upload, which can be larger and have more frames than `giphy.gif`; `giphy.webp` is lossy and can drop frames. Where the upload is gone, Giphy still answers `source.gif` with 200 and a 239,321-byte "THIS CONTENT IS NOT AVAILABLE" GIF, so check a download before converting it.
- The hero headline grows with enlarged text from a `1.125rem` floor under its fit-the-screen size, and its titles wrap only where that floor wins, through a container query at the same 15.86 × 1.125rem. A floor nearer the 19.17 px it shows at 320 px would win at default size, where 305 px of screen beside a classic scrollbar gives 18.2 px. At default size every width keeps its size; with the default font size doubled, through Chromium's `Page.setFontSizes` or Firefox's `font.size.variable.x-western`, and a 200% root font size in WebKit, the headline is 36 px at 320, 375 and 412 px in all three engines, and its height holds while titles type. Gecko's `font.size.systemFontScale` and `ui.textScaleFactor` changed nothing in headless desktop Firefox, and Playwright reaches no text-only zoom in any engine.
- Claude Code cloud sessions get their tools in two parts. The cloud environment's setup script serves every web repo that uses the environment and knows none of them, so it installs only what no repo pins: Vite+ through its official installer, fetched from raw.githubusercontent.com because vite.plus is off the network allowlist, Playwright's system packages and latest browsers, and Chrome Beta for the Playwright MCP. `.claude/hooks/setup-cloud-session.sh`, a SessionStart hook, installs what this repo pins: its Node.js, pnpm and dependencies through `vp install`, and its Playwright's browser builds. The default environment allows only the hosts builds need, since every allowed host is a source of injected instructions; research sessions run in a second environment with the same setup script, whose allowlist adds the research sites. https://code.claude.com/docs/en/cloud-environments#setup-scripts-vs-sessionstart-hooks

## Why not

- A Worker, through `adapter-cloudflare` or a `main` in `wrangler.jsonc`: every page is prerendered, so a Worker would only stand between a request and a static file. Its bundle also fails at startup in workerd, kit#15960: Rolldown emits `var __require = createRequire(import.meta.url)`, `import.meta.url` is `undefined` there, and the Worker stops with "The argument 'path' must be a file URL object, a file URL string, or an absolute path string. Received 'undefined'". Vite converts those `require`s only for `ssr.target: 'webworker'`, which `adapter-cloudflare` doesn't set. https://github.com/sveltejs/kit/issues/15960 https://github.com/vitejs/vite/pull/23759
- Smart Placement: it only moves where a Worker's fetch handler runs, and static assets are always served from the location nearest the request. https://developers.cloudflare.com/workers/configuration/placement/
- Argo Smart Routing: it speeds the path to an origin server, and the site has none. https://developers.cloudflare.com/argo-smart-routing/
- mdsvex, MDX or any component in a post: the feed carries the same HTML, and a component renders only on the site.
- Plausible: the site would load its script itself, where Cloudflare injects its own beacon at the edge.
- Trispace inlined into the stylesheet as a data URI: Chrome still decodes it after first paint, so text paints in the fallback first and shifts as much as before.
- `font-display: block`: invisible text is still laid out in the fallback, so the visible boxes around it shift when Trispace arrives. `optional` would leave a slow first load in the fallback font.
- `alias` for `#content`: deprecated in Kit 3, whose warning points to subpath imports: "The `config.alias` option is deprecated, and will be removed in a future version of SvelteKit. Use subpath imports instead: https://svelte.dev/docs/kit/$lib"
- `#lib` in tsconfig `paths`: Kit's docs warn that overriding `paths` can break things. https://svelte.dev/docs/kit/$app-tsconfig

## Constraints

- No `svelte.config.js`: its existence throws "`svelte.config.js` is no longer used. Please pass configuration via the `sveltekit(...)` plugin in your Vite config." `sveltekit(...)` in `apps/web/vite.config.ts` is async and takes one flattened config: what sat under `kit` moves to the top level, beside vite-plugin-svelte's options such as `preprocess`, `compilerOptions` and `inspector`. Vite awaits the promise in `plugins`. `vitePlugin` is gone too: "`config.vitePlugin` has been removed. Pass `vite-plugin-svelte` options directly to the `sveltekit(...)` Vite plugin". https://svelte.dev/docs/kit/migrating-to-sveltekit-3
- `apps/web/tsconfig.json` extends `$app/tsconfig` by that exact string. Kit compares it literally: anything else, even a relative path to the same file, warns "`tsconfig.json` should extend SvelteKit's built-in configuration:" and skips Kit's check that the config overrides nothing essential. https://github.com/sveltejs/kit/blob/%40sveltejs/kit%403.2.0/packages/kit/src/core/sync/write_tsconfig/index.js
- No `$lib`: an import of it fails the build with "`$lib` has been removed. Use `#lib` instead: https://svelte.dev/docs/kit/$lib."
- A `#lib` import names its file, extension included: `#lib/utils.js`, `#lib/components/ui/button/index.js`. Kit 3 no longer writes `#lib` into tsconfig `paths`, and TypeScript adds no extension or `/index` to a subpath import, so `#lib/constants` fails type checking with "Cannot find module '#lib/constants' or its corresponding type declarations." https://github.com/sveltejs/kit/pull/16736
- `apps/web/package.json` maps `#lib/*.js` to `./src/lib/*.ts`, ahead of `#lib/*`. TypeScript and Vite resolve `#lib/utils.js` to `utils.ts` on their own, but Node doesn't, and Playwright loads specs through Node: without the mapping, a spec importing `#lib/constants.js` stops with "Cannot find module '…/src/lib/constants.js' imported from". So a `.js` file in `src/lib` can't be imported through `#lib`.
- `typescript` stays on 6: `svelte-kit sync` reads tsconfig through `ts.sys`, which TypeScript 7's API lacks, and Kit's peer range is `^6.0.0`. With TypeScript 7 as `typescript`, sync fails with "Cannot read properties of undefined (reading 'readFile')". svelte-check still type checks with TypeScript 7, through `--tsgo` and `@typescript/native`, an alias of `typescript@7`. https://github.com/sveltejs/kit/blob/%40sveltejs/kit%403.2.0/packages/kit/src/core/sync/write_tsconfig/index.js
- `svelte-check --tsgo` writes transpiled components to `.svelte-kit/.svelte-check` and checks every file there. Only `--incremental` deletes a removed component's file, and only one its manifest recorded, so a file left by a run without it is still checked and fails on its own stale imports, with errors located under `.svelte-kit/.svelte-check/svelte/src/`, such as "Cannot find module './gone' or its corresponding type declarations." Deleting the folder clears such a file.
- `vp check` type checks what the build generates: on a fresh clone it fails with "File '$app/tsconfig' not found." and "Cannot find module '#content' or its corresponding type declarations.", so `sanity` builds first.
- `paths: {relative: false}` in `sveltekit(...)`: Cloudflare serves `404.html` at whatever depth a wrong address has, and Kit's default relative asset paths, `./_app/immutable/...`, would then resolve under that address and come back as the 404 page again, so a mistyped `/blog/<year>/<slug>` would get no CSS and never hydrate. https://svelte.dev/docs/kit/@sveltejs-kit-vite
- content-collections reads its config from `content/content-collections.ts`, through the Vite plugin's `configPath`. A collection's `directory` resolves relative to that file, hence `directory: 'blog'`; a wrong one finds nothing, logs "finished build of 1 collection and 0 documents", and prerendering then fails with `prerender_unseen_routes`. Its `defineConfig` takes `content`; `collections` warns "The configuration property "collections" is deprecated."
- `apps/web/components.json` sets `"lib": "#lib"`. The shadcn-svelte CLI defaults that alias to `$lib` and stops with "Config Error: Invalid import alias found: ("lib": "$lib") in components.json." With it, `shadcn-svelte add` installs into this app and writes imports such as `#lib/utils.js`.
- Prerendering gives `page.url` the origin `http://sveltekit-prerender` unless `paths.origin` is set, so `og:url` would ship as `http://sveltekit-prerender/about`. `og:url`, share links, the sitemap and the feed are built from `SITE_URL` in `apps/web/src/lib/constants.ts`.
- A prerendered `+server.ts` route becomes a file, and the host infers its type from the extension, so headers the route sets are lost: the feed would go out as `application/xml` instead of `application/rss+xml; charset=utf-8`. Headers go in `apps/web/static/_headers`, redirects in `apps/web/static/_redirects`. https://developers.cloudflare.com/workers/static-assets/headers/ https://developers.cloudflare.com/workers/static-assets/redirects/
- `trailingSlash` stays at Kit's default, `never`, which writes `/about` as `about.html`. Cloudflare's default HTML handling serves that at `/about` and answers `/about/` with a 307 to it. https://svelte.dev/docs/kit/page-options#trailingSlash https://developers.cloudflare.com/workers/static-assets/routing/advanced/html-handling/
- Cloudflare can't inject the Web Analytics beacon into a response with `Cache-Control: public, no-transform`. https://developers.cloudflare.com/web-analytics/get-started/
- Kit 3 exports the hook types from `@sveltejs/kit/hooks`. Importing `Handle` from `@sveltejs/kit` fails with "Module '"@sveltejs/kit"' has no exported member 'Handle'."
- enhanced-img only types imports that end in `?enhanced`, so an image chosen at runtime and given its own widths with `w` comes through `import.meta.glob` and its `query` object. A fixed image takes them in its `<enhanced:img src>`, as `?w=…`. https://svelte.dev/docs/kit/images
- enhanced-img can't serve an animated image. The vite-imagetools it runs opens every source with `sharp(path)`, without `animated: true`, so sharp reads only the first frame: at enhanced-img 1.0.1 and vite-imagetools 12.0.2, an 11-frame GIF comes out as one frame in AVIF, WebP and GIF alike, and `enhancedImages()` takes no options to change that. A PR adding an `animated` directive was closed unmerged. sharp 0.35.5 can't write an animated AVIF either: its docs say "AVIF image sequences are not supported", and given every frame it writes one still image with the frames stacked. https://github.com/JonasKruckenberg/imagetools/issues/726 https://github.com/JonasKruckenberg/imagetools/pull/454 https://sharp.pixelplumbing.com/api-output#avif
- vite-imagetools takes any query on an image import as a directive, `?url` included, and re-encodes the image from its first frame: a 420,802-byte, 11-frame WebP imported with `?url` came out as a 50,922-byte still. A post's animations are imported with no query, which vite-imagetools passes on to Vite's own asset handling untouched.
- Tailwind 4's `outline-hidden` sets `outline: 2px solid transparent` under `forced-colors: active`, where forced colours paint the transparent outline visible. On every button, it outlined all of them, unfocused too, so the buttons take it on `focus-visible` only. Forced colours drop the `box-shadow` ring, so without it a focused button showed nothing. https://tailwindcss.com/docs/outline-style
- Chromium paints its default focus ring, `outline: auto`, in the element's text colour: white on the share hub's tweet button, 2.51:1 against the panel behind it in light theme, and the page's colours on the testimonials' inverted cards, 1.63:1. Those links set their own outline colour.
- The header's `min-h-(--header-height)` needs `shrink-0`: the body is a column flexbox as tall as the screen, and squeezes the header back to 64 px under content that has wrapped.
- Lighthouse's default throttling simulates the load from what finished before the observed paint, and models HTTP/1.1, which `wrangler dev` serves, as six connections per origin where Cloudflare serves h2. Against `vp run preview` it so estimates LCP higher than the same build served over h2: 2.7 s against 2.1 s on the home page before 1.3. https://github.com/GoogleChrome/lighthouse/blob/main/docs/throttling.md
- oxfmt formats the code fences in Markdown, sorting the imports and Tailwind classes of a post's code samples, which readers see. An override sets `embeddedLanguageFormatting: 'off'` for `apps/web/content/blog/**`; without it `vp check` stops with "error: Formatting issues found" and lists the posts. https://oxc.rs/docs/guide/usage/formatter/config-file-reference.html
